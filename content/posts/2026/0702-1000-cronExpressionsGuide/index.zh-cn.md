Cron 是几乎所有定时任务背后默默干活的老黄牛——日志轮转、备份、缓存预热、报表邮件。它的语法很紧凑，这也正是它容易坑人的原因：一个字段放错，"每周一"就变成了"每天"。本文逐字段讲清 Cron 表达式、特殊字符，并重点点出那些真正会引发线上事故的坑。

<!--more-->

### 五个字段

标准 Cron 表达式由五个以空格分隔的字段组成：

```
┌───────────── 分钟   (0 - 59)
│ ┌─────────── 小时   (0 - 23)
│ │ ┌───────── 日     (1 - 31)
│ │ │ ┌─────── 月     (1 - 12)
│ │ │ │ ┌───── 星期   (0 - 6，周日 = 0)
│ │ │ │ │
* * * * *
```

所以 `30 2 * * *` 表示"每天 02:30"，`0 9 * * 1` 表示"每周一 09:00"。

有些调度器（Quartz、Spring、部分 Kubernetes 工具）会在最前面加一个**秒**字段，变成六个字段。而大多数 Linux 上的 Vixie cron **没有**秒字段。写之前一定要清楚你面对的是哪种方言——"表达式一挪到别的系统就失灵"的困惑，绝大多数都源于此。

### 特殊字符

| 字符 | 含义 | 示例 |
|------|------|------|
| `*`  | 每一个值 | `* * * * *` = 每分钟 |
| `,`  | 列表     | `0 0,12 * * *` = 午夜和正午 |
| `-`  | 范围     | `0 9-17 * * *` = 09:00–17:00 每小时 |
| `/`  | 步长     | `*/15 * * * *` = 每 15 分钟 |
| `L`† | 最后     | `0 0 L * *` = 每月最后一天 |
| `#`† | 第 N 个星期几 | `0 0 * * 5#3` = 每月第 3 个周五 |

† `L` 和 `#` 是 Quartz/扩展语法，标准 Vixie cron 不支持。

步长可以和范围组合：`0-30/10` 表示第 0、10、20、30 分钟。而分钟字段的 `*/20` 会在 :00、:20、:40 触发——**不是**从你部署那一刻起每隔 20 分钟滚动一次。Cron 永远对齐挂钟时间。

### 读懂真实排程

- `*/5 * * * *` —— 每 5 分钟
- `0 * * * *` —— 每小时整点
- `0 0 * * *` —— 每天午夜
- `0 3 * * 1-5` —— 工作日 03:00
- `0 0 1 * *` —— 每月 1 号午夜
- `15 14 1 * *` —— 每月 1 号 14:15
- `0 22 * * 1-5` —— 周一到周五 22:00

### 真正会坑到你的地方

**1. "日"和"星期"是"或"，不是"且"。** 这是最著名的坑。`0 0 13 * 5` 并**不**表示"13 号的周五"。当"日"和"星期"两个字段**都**被限定（都不是 `*`）时，只要**任意一个**匹配，cron 就会执行。于是这条表达式会在**每个** 13 号**以及每个**周五都触发。想要"黑色星期五（13 号周五）"，得靠应用层逻辑，光靠 cron 做不到。

**2. 时区。** 传统 cron 按服务器本地时间运行。如果服务器是 UTC，而你按 Asia/Shanghai 思考，那 `0 9 * * *` 对你来说是 17:00 而不是 09:00。夏令时切换更糟：排在 02:30 的任务在切换那天可能跑两次或一次都不跑。服务器建议统一用 UTC，或使用支持显式 `CRON_TZ=` / 时区设置的调度器。

**3. 秒字段。** 把一条六字段的 Quartz 表达式直接粘进 Linux crontab，整体就会错位一格——你的"分钟"变成了 cron 根本没有的"秒"，行为立刻跑偏。粘贴前先数字段数。

**4. 任务重叠。** 到点了 cron 就会启动新的一次，哪怕上一次还没跑完。一个平时 2 分钟、偶尔 20 分钟的任务，若排成 `*/5`，就会堆积。给耗时任务加锁（`flock`），或用能保证"不并发运行"的调度器。

**5. 运行环境。** Cron 以极简环境运行——没有 `.bashrc`、`PATH` 很裸、`HOME` 也常常不是你以为的那个。"在我 shell 里好好的，一进 cron 就挂"几乎总是 PATH 或环境变量缺失。请使用绝对路径，并在 crontab 顶部设置好所需变量。

### 先验证，再信任

验证表达式最稳妥的方式，是把接下来几次的触发时间以真实日期列出来，并用自然语言把排程读回一遍。我做了一个免费、纯浏览器运行的[Cron 表达式生成器](https://suzf.net/zh/tools/cron-generator)，正是干这个的：可视化编辑每个字段、给出人类可读的描述、并在你把它写进 crontab 之前预览接下来五次执行。所有计算都在页面本地完成——不上传任何内容。

### 小结

- 先数字段数（5 还是 6），弄清 cron 方言。
- Cron 对齐挂钟时间；步长不是"滚动"间隔。
- "日"和"星期"都被设定时是"或"的关系。
- 固定时区，并防范任务重叠。
- 上线前务必预览接下来的执行时间。

Cron 对一点点严谨很买账。把字段设对一次、验证好后续触发时间，它就能默默替你干上好几年。
