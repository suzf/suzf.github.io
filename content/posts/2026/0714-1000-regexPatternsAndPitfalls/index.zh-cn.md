正则表达式是一门描述文本模式的小语言，和任何利器一样，它是双刃剑。用得好，它能替掉一大页字符串处理代码；用得糙，它会引发隐蔽的 bug，甚至造成拒绝服务式的宕机。本文汇总值得记住的套路和值得敬畏的坑。

<!--more-->

### 你用得最多的零件

- **字符类：** `\d` 数字、`\w` 单词字符（`[A-Za-z0-9_]`）、`\s` 空白；大写取反（`\D`、`\W`、`\S`）。`[abc]` 是自定义集合，`[^abc]` 是它的取反，`[a-z]` 是范围。
- **量词：** `*`（0 个以上）、`+`（1 个以上）、`?`（0 或 1）、`{n}`、`{n,}`、`{n,m}`。
- **锚点：** `^` 开头、`$` 结尾、`\b` 单词边界。它们匹配的是*位置*，不是字符。
- **分组：** `(...)` 捕获、`(?:...)` 非捕获、`(?<name>...)` 命名。用 `$1`（替换）或 `\1`（模式内）反向引用。
- **或：** `a|b` 表示 a 或 b。注意优先级：`^cat|dog$` 是 `(^cat)|(dog$)`，不是 `^(cat|dog)$`。

### 标志位改变一切

- `g` —— 全局，查找所有匹配，而不只是第一个。
- `i` —— 忽略大小写。
- `m` —— 多行：`^`/`$` 在每一行都匹配，而不只是整个字符串的首尾。
- `s` —— dotall：`.` 也匹配换行符（默认不匹配）。
- `u` —— unicode：处理基本多文种平面之外的字符和 `\p{...}` 属性时需要。

很大一部分"我的正则匹配不上"的 bug，其实只是漏了 `m`、`s` 或 `u`。

### 值得收藏的套路

```
# 去掉首尾空白
^\s+|\s+$

# 把连续空白压成一个空格
\s+   →   " "

# 类 ISO 日期  2026-07-14
^\d{4}-\d{2}-\d{2}$

# IPv4（宽松——只校验形状，不校验 0–255 范围）
^(\d{1,3}\.){3}\d{1,3}$

# 从标题生成 slug（替换非字母数字）
[^a-z0-9]+   →   "-"
```

关于那个 IPv4 套路要提一句：它也能匹配 `999.999.999.999`。正则擅长校验*形状*；范围校验（每段 0–255）用纯正则写起来很别扭，交给代码更好。这是一条通则——用正则做切分，用代码校验语义。

### 真正会引发 bug 的坑

**1. 贪婪量词抓得太多。** 对 `<a><b>` 用 `<.+>` 会匹配*整个* `<a><b>`，而不是 `<a>`，因为 `+` 是贪婪的、会从末尾回溯。改用懒惰版 `<.+?>`，或者更好地，用取反字符类 `<[^>]+>`。

**2. 忘了加锚点。** 用 `\d{4}` 校验输入会欣然接受 `abc1234xyz`，因为它只需要在*某处*找到四个数字。要校验整个字符串，就把两端都锚住：`^\d{4}$`。

**3. 元字符没转义。** `.` `+` `*` `?` `(` `)` `[` `]` `{` `}` `^` `$` `|` `\` 都是特殊字符。要匹配域名里的真点号得写 `\.`——把 `example.com` 当模式，它也会匹配 `exampleXcom`。往模式里拼入用户输入前，先转义。

**4. 灾难性回溯（ReDoS）。** 像 `(a+)+$` 或 `(.*)*` 这样嵌套或重叠的量词，遇到不匹配的输入时会让引擎去探索指数级数量的路径。一个精心构造的字符串就能把一个 CPU 核占满几秒甚至几分钟——这是 Web 应用里真实存在的拒绝服务向量。避免在重叠字符集上嵌套量词；在支持的地方用占有量词/原子组，或换用不回溯的引擎（RE2）。

**5. Unicode 的意外。** 不加 `u` 标志时，`.` 和 `\w` 是按 UTF-16 码元来数的，于是一个 emoji 或一个中文字可能被算成两个，而 `\w` 也匹配不上 `é` 或 `中` 这样的字母。加上 `u`，并用 `\p{L}` 表示"任意字母"。

**6. 别用正则解析结构化格式。** HTML、JSON、嵌套括号都不是*正则*语言——正则从根本上无法匹配任意深度的嵌套结构。请用真正的解析器。正则适合从这类文本里抽取简单、扁平的模式，而不适合理解它的结构。

### 小结

- 校验时加锚点；把量词改懒惰，或用取反字符类。
- 转义用户输入和字面元字符。
- 警惕嵌套量词——那是 ReDoS 陷阱。
- Unicode 加 `u`；别用正则解析 HTML/JSON。
- 上生产前先交互式测试你的模式。
